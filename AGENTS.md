- Company segments live in public.company_segments (per org, managed list) referenced by companies.segment_id; companies.segment text is deprecated and must not be read or written — keeps segment names consistent and renameable.
- Inbound webhook and spreadsheet import resolve company+contact only through public.resolve_company_contact (import preview via preview_import_resolution); deals are written with company_id + lead_contacts, never legacy lead name/email/phone/company fields — one shared rule keeps both entry points consistent.
- companies.trade_name_source ('provided'|'placeholder') decides whether inbound data may replace the trade name: only placeholder names (from contact/e-mail/Instagram/'Sem nome') are replaced, and any manual edit sets 'provided' — protects real names from webhook overwrites.
- Companies/Contacts list screens read through list_companies / list_contacts (SECURITY INVOKER over *_overview views, security_invoker) with filters as jsonb; list state lives in the URL via useUrlListState — server-side paging/sorting and shareable links.
- WhatsApp → CRM (docs/WHATSAPP.md): conversas ligam a negócios só por contacts.phone_key → lead_contacts de negócio aberto (única exceção: frase de boas-vindas de número sem contato → o único formulário recebido a até 10 min, §17), e a IA muda etapa só por server/negocios/etapa.ts (moverEtapa) — contato sem telefone ou sem lead_contacts fica invisível, e outro caminho pularia SLA/webhook da etapa.
- Inbound webhook on an existing deal (same company + funnel): only a won/inactive/archived deal re-enters the first stage; an open one keeps its stage and gets a note — a lead already talking to sales must not fall back to Novo Lead and re-trigger the Softeo bot.
- Task types live in public.task_types (per org, db/65_tipos_tarefa.sql) with subtypes in task_subtypes; tasks.task_type stays the type *code* ('follow_up', 'meeting', 'ticket'...) and a trigger fills task_type_id — server inserts keep using codes, and the type's `action` (orbi_meeting/orbi_ticket) is what will drive integrations, never an if on the code.
- Orbi (docs/ORBI.md): tasks whose type action is 'orbi_meeting' are queued to Orbi by the z_tasks_orbi_fila trigger (db/66) and only become completed through Orbi's signed callback (server/orbi.ts) — or, for a demo Bia books (server/agente/chatvolt.ts /agendar), inserted already 'accepted' from Orbi's confirmed booking response; any server write that sets external_status together with other fields is treated as integration traffic, never as a user edit — don't touch external_* from other paths.
- Chatvolt conversations (0573) enter as channel provider 'chatvolt' via the agent's outbound webhook (docs/WHATSAPP.md §20), so the same WhatsApp analysis turns a meeting a human agrees in the Chatvolt inbox into a 'meeting' task (→ Orbi); messages carry raw.autor ('lead'|'ia'|'equipe') — the analysis must never count the AI's messages as human attendance, and never queue a second meeting on a day the deal already has one.
- Bia (Chatvolt, docs/WHATSAPP.md §19): demo só com buffet infantil ou espaço de eventos (barreiraDaDemo) e consultor só depois que o lead ouviu os valores (barreiraDoHandoff; cliente, reclamação e pedido de pessoa passam); fora do perfil ela fecha sozinha (vídeo + checkout do Starter), e quem acha caro recebe a promoção do anual antes de ser arquivado — o CRM é quem segura a regra, o prompt sozinho não segura.
- Demo confirmation (docs/ORBI.md, "Confirmação 3 h antes"): the worker job server/agente/confirmacao-demo.ts sends the Chatvolt WhatsApp template (oni_confirmacao_demo_v3) to leads whose Orbi demo task is 'accepted' and starts within 3 h, once per task via public.demo_confirmations (no automatic retry); the Meet link comes only from tasks.meeting_url and the button URL must stay dynamic (https://meet.google.com/{{1}} with example) — the Chatvolt template form creates static buttons, so create templates through POST /api/whatsapp/templates; off until CONFIRMACAO_DEMO_ATIVA=1 and the template is approved.
- Form welcome (docs/WHATSAPP.md §17, "Pelo Chatvolt"): with BOAS_VINDAS_CHATVOLT=1 the CRM sends oni_primeiro_contato through the Chatvolt template API (server/canais/chatvolt-template.ts, shared with the demo confirmation) instead of the n8n→Meta Graph path, which failed with error #10 from the n8n token; same per-phone lock (channel_welcomes), no automatic retry, and the phrase-triggered audio welcome stays on n8n/Evolution.
